# Ustaz AI — виртуальный наставник студента колледжа

## Контекст
Проект студента колледжа (Алматы) для городского конкурса «Технологии. Интеллект. Будущее» /
«Зияткерлік. Болашақ. Технологиялар.» (Авиационный колледж АО «Академия гражданской авиации»).
- Направление: **AI Education — Искусственный интеллект в образовании**
- Срок подачи заявки: 20 ноября 2026, финал: 25 ноября 2026
- Защита: 7 минут презентация + 3 минуты вопросы жюри, живая демонстрация прототипа
- Жюри может дать дополнительное условие / короткое практическое задание на защите,
  поэтому код должен быть простым и легко изменяемым (промпты и материалы — в отдельных файлах)

Также нужен **AI-паспорт проекта**: инструменты ИИ, вклад каждого, основные промпты, что создал ИИ,

## Идея продукта
Ustaz AI (Ұстаз — «наставник») — веб-приложение: пользователь входит по логину и паролю,
выбирает **предмет**, затем **режим**. ИИ работает **только по учебным материалам** предмета
и даёт ссылку на лекцию и раздел. Если ответа в материалах нет — честно говорит об этом.

### Предметы (демо)
1. **Информатика** — алгоритмы, системы счисления, основы Python, условия и циклы
2. **Математика** — квадратные уравнения, тригонометрия, производная, логарифмы
Формулы рендерятся через **KaTeX**. Демо-лекции написаны ИИ → должны быть проверены
преподавателем (п. 5.5 положения; пометка — в README и AI-паспорте, не в интерфейсе — по решению автора).

### Режимы для студента
1. **Объясни** — ответы со ссылкой на лекцию; вне материала — «этого нет в курсе».
2. **Сократ** — помощь с задачей без готового ответа. Главная фишка проекта.
3. **Проверь меня** — 3 вопроса по теме; при ошибке объясняет по-другому.
4. **Тренажёр экзамена** — билет, ответ, оценка по рубрике.

### Режимы для преподавателя (преподаватель видит и режимы студента)
6. **Генератор тестов с проверкой** — генерация JSON-теста + второй проход ИИ-рецензента.
   Генерировать порциями (≈5 вопросов) из-за таймаута функций.
7. **Аналитика** — только тема, режим, предмет, время, верно/неверно — **без персональных данных**.

### Вход
- Учётные записи в `netlify/lib/users.mjs`, пароли только как хэш scrypt.
  Новый хэш: `node scripts/hash-password.mjs <пароль>`.
- Демо-логины: `student`, `teacher`. Пароли НЕ хранятся в репозитории (он публичный) —
  они у автора и в локальном `.env` (RT_LOGIN / RT_PASSWORD для стресс-теста).
- Токен подписан HMAC (`AUTH_SECRET` в `.env`), срок 12 часов. Все функции ИИ проверяют токен.

### Языки
Интерфейс и ответы ИИ на **казахском и русском** (переключатель Қаз/Рус).
Казахские тексты интерфейса нужно проверить носителю языка.

## Стек
- Фронтенд: чистые HTML / CSS / JS в `public/` (без фреймворков и сборки)
- Бэкенд: **Netlify Functions** (v2, `.mjs`) в `netlify/functions/`, общий код — `netlify/lib/`
- ИИ: **Gemini API** (REST `generateContent`), `thinkingLevel: "minimal"`.
  Основная модель **`gemini-3.1-flash-lite`** (1–3 сек, читает фото, держит правила),
  цепочка запасных `GEMINI_FALLBACK_MODEL=gemini-3.5-flash-lite,gemini-3.5-flash`.
  `gemini-2.5-flash` недоступна новым ключам, `gemini-3.8-flash` слишком медленная (>20 сек).
- **Лимиты бесплатного тарифа:** ~5 запросов/мин на модель и **всего 20 запросов/сутки у
  `gemini-3.5-flash`** (поэтому она лишь последняя запасная). Google иногда отвечает 503
  «high demand» — тогда идёт следующая модель цепочки; фронтенд один раз сам повторяет запрос
  при таймауте/перегрузке. Ошибки для пользователя: rate_limit / daily_limit / overloaded / timeout.
  **Решение автора (15.11): остаёмся на бесплатном тарифе.** Следствия для защиты: паузы между
  действиями, жюри не открывает сайт одновременно, обязательно запасное видео демо.
- `.env`: `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_FALLBACK_MODEL`, `AUTH_SECRET`
  (все четыре задать в настройках сайта на Netlify)
- Хранилище: **Netlify Blobs** — `analytics` (события) и `lectures` (лекции преподавателей)
- Локальный запуск: `netlify dev` → http://localhost:8888 (после правки `.env` — перезапуск).
  Не запускать два `netlify dev` одновременно: они делят `.netlify/functions-serve` и ломают
  друг другу сборку функций («Cannot find module …/lib/…»).
- Ограничение: функция на бесплатном Netlify ≈10 секунд — запрос к ИИ обрывается через 9 сек

### Проверка результатов ИИ (главный аргумент для жюри)
1. **Цитаты:** ИИ обязан привести дословную цитату из лекции; сервер ищет её в тексте
   (`findQuote` в content.mjs, формулы LaTeX и «a/b» сравниваются одинаково) → ✓ / ⚠ у ссылки.
   Клик по ссылке открывает лекцию с подсвеченным разделом.
2. **Тесты:** генератор → ИИ-рецензент → программная проверка (4 варианта, ключ, раздел, цитата).
3. **Экзамен:** баллы пересчитывает сервер, рубрика зашифрована (AES-GCM).
4. **Материалы преподавателя:** ИИ-методист ищет ошибки до публикации + обязательное
   подтверждение преподавателя (п. 5.5). Демо: `docs/demo-lecture-with-errors.txt` (3 ошибки).
5. **Стресс-тест безопасности:** `node scripts/redteam.mjs` (атаки в `tests/redteam-cases.json`,
   проверки программные) → `docs/redteam-report.md`.
Фото решения: `docs/demo-photo-solution.jpg` (ошибка 49+40 в дискриминанте).

```

scripts/           hash-password.mjs, redteam.mjs
tests/             redteam-cases.json
docs/              демо-материалы для защиты и отчёт стресс-теста
```

## Как работаем (важно)
